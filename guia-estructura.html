🚌 FusaRoute Frontend: Guía Rápida

Esta guía explica la estructura y el funcionamiento del frontend para facilitar el estudio y la revisión técnica.

📂 Estructura del Proyecto

src/app/core/ Cosas que cargan una sola vez: interceptores, guards y servicios globales. Es el "corazón" técnico.
src/app/pages/ Componentes de pantalla completa (Login, Registro, Catálogo). Cada carpeta es una "página".
src/app/services/ Lógica de comunicación con la API. Aquí se definen los métodos HTTP (GET, POST, etc.).
src/app/models/ Interfaces de TypeScript que definen la forma de los datos (DTOs) que vienen del backend.
}

⚙️ Funcionamiento General

El flujo de datos sigue este camino:

Usuario ➔ Componente (UI) ➔ Servicio (API) ➔ Interceptor (JWT) ➔ Backend
  • Zoneless / Signals: El proyecto usa Angular moderno. En lugar de actualizar toda la pantalla, usamos signals para que solo cambie el dato exacto que varió.
  • Intercepción de Tokens: El HttpInterceptor adjunta automáticamente el token JWT en la cabecera Authorization: Bearer ... de cada petición.
  • Guards: El AuthGuard protege rutas como el Perfil, redirigiendo al Login si no hay sesión activa.

📄 Archivos Clave (Lo más importante)

  • app.routes.ts: El mapa de navegación. Aquí defines qué URL lleva a qué página.
  • auth.service.ts: Maneja el login, el registro y el estado de la sesión (quién está conectado).
  • route.service.ts: Se encarga de traer las rutas y tarifas desde la API.
  • auth.interceptor.ts: El "portero" que pone el token en cada llamada al servidor.
  • app.component.ts: El componente raíz que sostiene el Header y el contenido principal.

⚠️ Conceptos Críticos para el Comité

1. ¿Cómo sabemos si el usuario está autenticado?
El AuthService revisa el localStorage y el vencimiento del token. Usamos un signal isLoggedIn para reaccionar en tiempo real.

2. ¿Qué pasa si la API devuelve un error 401?
El interceptor detecta el código 401, limpia el token del navegador y redirige al usuario a la pantalla de Login.

3. ¿Cómo evitamos que la app sea lenta?
Usando Signals para evitar detecciones de cambios innecesarias y optimizando las llamadas a la API mediante servicios especializados.
